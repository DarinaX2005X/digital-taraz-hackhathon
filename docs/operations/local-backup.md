# Резервная копия локальных данных

Эти команды предназначены для самостоятельного запуска Tirlik с локальным PostgreSQL и файловым хранилищем в `.local-data`. Они сохраняют рабочие данные без `.env` и других секретов.

Перед созданием копии или восстановлением остановите приложение:

```powershell
node scripts/dev/stop.mjs
```

Команда откажется продолжать, если собственное приложение Tirlik не подтверждено как остановленное. На всё время операции она удерживает блокировку запуска, поэтому приложение не сможет стартовать посреди снимка или восстановления. Docker Desktop и локальный PostgreSQL должны быть доступны; команда запускает только собственный контейнер PostgreSQL, если он остановлен.

## Создание и проверка

Создать копию в новом каталоге с автоматически выбранным именем:

```powershell
node scripts/ops/local-data.mjs backup
```

По умолчанию копия появится в `.local-data/backups/`. Можно указать новый каталог, который ещё не существует:

```powershell
node scripts/ops/local-data.mjs backup --output D:\tirlik-backups\before-update
```

Проверить уже созданную копию без изменения текущих данных:

```powershell
node scripts/ops/local-data.mjs verify --from D:\tirlik-backups\before-update
```

Копия представляет собой самостоятельный каталог. В него входят:

- PostgreSQL в переносимом custom dump;
- весь каталог `TIRLIK_DATA_DIR`, включая загруженные источники и созданные экспорты;
- весь каталог `.local-data/workflow` с состоянием локальных процессов;
- `manifest.json` с размерами и SHA-256 каждого файла, дампа и применённых миграций.

В копию не входят `.env*`, ключи и другие секреты, production build, кэши, логи, Mailpit и служебное состояние запущенного процесса. Команда сначала пишет временный каталог, проверяет его содержимое и лишь затем публикует готовую копию. Существующий каталог никогда не перезаписывается.

## Восстановление

Сначала отдельно проверьте выбранную копию, затем восстановите её:

```powershell
node scripts/ops/local-data.mjs verify --from D:\tirlik-backups\before-update
node scripts/ops/local-data.mjs restore --from D:\tirlik-backups\before-update
```

Восстановление повторно проверяет хеши, полный набор файлов и совместимость применённых миграций до изменения текущих данных. Затем оно:

1. создаёт и проверяет автоматическую копию текущего состояния в `.local-data/backups/pre-restore-*`;
2. готовит файловые деревья в отдельном каталоге внутри `.local-data`;
3. заменяет PostgreSQL одной транзакцией `pg_restore --clean --if-exists --single-transaction`;
4. атомарно подменяет каталоги файлов и workflow;
5. при ошибке возвращает прежние каталоги и базу из автоматической копии.

После успеха автоматическая копия состояния до восстановления сохраняется, а путь к ней печатается в терминале. Tirlik не удаляет пользовательские резервные копии и не применяет к ним автоматическое правило хранения. Удаляйте старые копии вручную только после отдельной проверки более новой копии и успешного запуска приложения.

Если команда сообщает `RESTORE_ROLLBACK_FAILED`, не запускайте приложение. Сохраните указанный каталог `pre-restore-*`, устраните проблему с диском или PostgreSQL и восстановите именно эту копию. Команды не удаляют исходную копию, из которой выполнялось восстановление.
