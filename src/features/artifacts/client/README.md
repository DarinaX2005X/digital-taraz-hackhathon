# Artifact client checkpoint

This package provides client persistence, grouping, autosave, session privacy and typed HTTP transport. It consumes the canonical command, content, receipt and conflict schemas. The history route mounts version previews, checked undo/redo, lifecycle actions and reviewed draft recovery; editing engines belong to their feature modules.

## Integration contract

1. Fetch the current authenticated artifact snapshot. Construct `createArtifactPrivacy` from its `viewer` and the IDs actually authorized by those snapshots. Never derive authority from local preferences, a cached account name or a route ID. For a multi-artifact group, all affected artifacts must be authorized before opening their outbox.
2. Open `openArtifactCache(privacy)`. The database partitions all draft/pending records by user and workspace; each draft also has an artifact ID. A persisted revocation token and monotonic workspace authorization version invalidate other open connections. Suspended/closed leases cannot read, write or complete a prior transaction.
3. Construct `createArtifactAutosave({ privacy, cache, submit: artifactSubmit(artifactClient), onConfirmed, flushGroups })`. The typed HTTP adapter enforces a finite timeout and bounded response body, same-origin/no-store requests, `X-Tirlik-User-Id`, expected workspace/authz version, and `Idempotency-Key = commandGroupId`. It validates responses and maps C4 errors to `ArtifactRequestError`, retaining HTTP privacy statuses even for malformed upstream bodies. It never retries automatically.
4. Call `recover()` before new commands. Recovery loads pending records and recognizes standalone drafts but never submits them. The editor reads authorized drafts through `cache.getDraft()` and validates its current engine/version before presenting recovery. Never silently replace a newer server snapshot with local content.
5. Each edit uses a monotonically increasing draft generation and `writeDraft()` with canonical `ArtifactContent`. Keep the editor's live content intact when this call rejects. `locallyPersisted` becomes true only after the IndexedDB transaction finishes. A storage error is not a successful local save.
6. The engine adapter passes `createCommandGrouping` the complete change from the group's original base. Typing replaces that group's pending content for 700 ms; a selection/base change ends it. Paste, formatting, drag-end and one AI package are single immediate groups. The adapter must not submit intermediate drag frames or start a rival Tiptap/Univer/Fabric history stack. It owns semantic operations and rebasing, not this generic grouping layer.
7. `onReady` calls `autosave.enqueue(group, draftGenerations)`. Every command is persisted before submission. A partition-local monotonic sequence is assigned atomically on first insertion, so recovery preserves enqueue order even when timestamps match; retries keep the original sequence. An ambiguous response blocks replay until explicit `retry()`, preserving every command ID and the exact payload. Changed content requires new IDs. Server receipt validation checks the submitted group, actor, affected IDs and new revisions before acknowledging it. Cleanup cannot erase a newer generation.
8. Update the engine's authoritative base from `onConfirmed`. An edit created while a prior save is pending must be rebuilt against the acknowledged base by the engine adapter. This package does not invent automatic merging or rewrite an immutable submitted command. Unexpected callback failure blocks further work without replaying the already acknowledged command.
9. `flush()` first ends the grouping window, waits for local writes and the active server submission, and returns true only with no unacknowledged draft/command. Use that boolean before close, selection/navigation or export. It does not silently retry after a network error, conflict or expired session.

## Privacy and recovery

A C4 401 suspends the privacy boundary. The low-level `resumeAfterAuthentication()` accepts the same user/workspace and authorization version only; it does not retry. The session-level recovery instead opens a new controller from fresh server authority, revalidates candidate IDs through the bounded access endpoint, and retains the original operation ID, body and expected authorization version. A harmless authorization-version advance does not delete drafts or automatically submit them. Unlisted records remain quarantined; only explicitly unavailable artifacts are purged. A workspace membership denial purges that workspace, and an account switch purges all previous-user partitions. Late callbacks are ignored after expiry, revoke, signout or disposal.

409 keeps both the local content and safe server conflict references. It blocks generic retry. The remaining conflict feature must read the current authorized snapshot to show the server alternative; hashes and IDs are not content. No force overwrite or automatic merge is implemented here.

For `AccountMenu`, wire an explicit save/discard decision through `beforeSignOut`. Saving must return true from `session.flush()` before exit proceeds. Only confirmed successful signout calls `confirmedSignedOut()` through `onSignedOut`; it closes the boundary and removes all of that user's workspace caches. A false cleanup result must be disclosed, not described as successful device cleanup. Other users' partitions are untouched. Unmounting should call `dispose()` and close the database connection; this cancels the session lease but does not pretend the server mutation was cancelled or discard persisted work.

The IndexedDB cache is local, unencrypted, account-scoped recovery storage, not an authorization authority or a defense against malicious scripts running in the same origin. The authenticated server always enforces access. Do not store authentication/session secrets here. Reopening a cache requires fresh server authority, including after signout or permission changes.

`putHistory` persists only a canonical, authorized, last-100 history response. `getHistory` is a recovery read, not fresh permission to undo or redo: refresh eligibility from the server first. The same revocation epochs protect history and drafts. `listPending(artifactId)` excludes unrelated outbox groups, but a group involving an unauthorized material remains inaccessible as a whole. `discardReviewed(drafts, pending)` is reserved for an explicit reviewed resolution; it atomically compares every stored record and refuses to erase concurrently changed content. Callers must reconcile uncertain writes before offering discard.

The version-2 database upgrade is additive. The operations journal persists rename, move, lifecycle, duplicate, branch, restore-version and checked undo/redo requests before network submission. A recovered unknown outcome blocks another intent until an explicit same-ID reconciliation; definitive rejected operations can be dismissed. `prepareHistoryOperation` consumes only a fresh server history response and uses every affected artifact revision plus the server's source revision vector.

`useArtifactSession(initial)` from `../ui/use-artifact-session` composes `createArtifactSession` with the shared identity epoch gate. Mount it once per artifact/actor, never per revision, locale or dialog. Render private content only when `privateVisible && state.snapshot`; enable edits only after `state.storageReady`, permission checks and explicit recovery decisions. Session methods include `writeDraft(LocalDraft)`, `enqueue(CommandGroupInput, draftGenerations)`, `flush()`, `retrySave()`, `pollEvents()`, checked history operations and account cleanup. The editor owns its command grouping instance: call `grouping.flush()` before `session.flush()`. The session deliberately does not invent semantic edits or rebase an immutable submitted group.

Build target preconditions with `createEditorArtifactState(snapshot)` from `./snapshot-state`, `MerkleJson` and `ArtifactDraft.target(stableId)`. Unlike the fresh-content constructor, this editor projection preserves declared missing bindings/locks. A target hash includes metadata and stable location, not only node content. Only metadata-bearing missing IDs are exposed in the snapshot; new node IDs must be fresh UUIDs, and the server checks its complete retired-ID history. After acknowledgement, rebuild subsequent unsent edits against the fresh server snapshot while retaining newer local draft generations. Do not create a parallel engine undo stack. Controlled forms must remain outside the private rendering subtree during same-user authentication; do not restore old-authority form contents after access/account changes.

## Evidence and remaining scope

Focused Node tests use `fake-indexeddb`'s actual IndexedDB API implementation with isolated factories. They cover transaction completion, connection reopen, auth/account/workspace/artifact isolation, revocation across connections, abort races, generation ordering, quota errors, stable replay, same-user reauthentication, 409 preservation, receipt mismatch, signout cleanup and grouping/flush. They do not prove disk durability, private mode, browser lifecycle/eviction or cross-browser behavior.

Focused transport tests additionally cover relative endpoints, request flags, canonical idempotency, actor/workspace/artifact/version mismatch, bounded responses, timeouts, abort and safe errors. They mock HTTP responses and do not prove the mounted handlers.

The mounted history page supports fresh authorized server alternatives, per-draft comparison before discard, separate branches without silently deleting originals, same-ID reconciliation of uncertain writes, lifecycle dialogs, bounded versions and current-source freshness. Workspace events trigger narrow refreshes with hidden-tab pause and backoff. Document/table/plan previews are bounded semantic views; design is a layer/property view and private image assets are not resolved yet. SQL and real HTTP acceptance are tracked separately by the integration suite; mocked transport tests alone do not establish them. No browser navigation, screenshot, renderer, CUA or browser automation has been used. Visual, keyboard, mobile, IndexedDB browser lifecycle and engine interaction remain user-owned checks.
