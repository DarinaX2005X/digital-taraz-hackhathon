# Artifact client checkpoint

This is the first 03.1 client persistence/grouping/autosave checkpoint, not the complete editor or an HTTP integration claim. It consumes the canonical command, content, receipt and conflict schemas. No root page, editor engine, history dialog or network handler is mounted by this package.

## Integration contract

1. Fetch the current authenticated artifact snapshot. Construct `createArtifactPrivacy` from its `viewer` and the IDs actually authorized by those snapshots. Never derive authority from local preferences, a cached account name or a route ID. For a multi-artifact group, all affected artifacts must be authorized before opening their outbox.
2. Open `openArtifactCache(privacy)`. The database partitions all draft/pending records by user and workspace; each draft also has an artifact ID. A persisted revocation token and monotonic workspace authorization version invalidate other open connections. Suspended/closed leases cannot read, write or complete a prior transaction.
3. Construct `createArtifactAutosave({ privacy, cache, submit, onConfirmed, flushGroups })`. `submit` is the explicit, typed `ArtifactSubmit` port. The eventual HTTP adapter must enforce a finite timeout, same-origin/no-store, `expectedUserId`, `expectedAuthzVersion`, and `Idempotency-Key = commandGroupId`, and map C4 errors to `ArtifactSubmissionError`. This checkpoint does not invent a route while the service is still being implemented.
4. Call `recover()` before new commands. Recovery loads pending records and recognizes standalone drafts but never submits them. The editor reads authorized drafts through `cache.getDraft()` and validates its current engine/version before presenting recovery. Never silently replace a newer server snapshot with local content.
5. Each edit uses a monotonically increasing draft generation and `writeDraft()` with canonical `ArtifactContent`. Keep the editor's live content intact when this call rejects. `locallyPersisted` becomes true only after the IndexedDB transaction finishes. A storage error is not a successful local save.
6. The engine adapter passes `createCommandGrouping` the complete change from the group's original base. Typing replaces that group's pending content for 700 ms; a selection/base change ends it. Paste, formatting, drag-end and one AI package are single immediate groups. The adapter must not submit intermediate drag frames or start a rival Tiptap/Univer/Fabric history stack. It owns semantic operations and rebasing, not this generic grouping layer.
7. `onReady` calls `autosave.enqueue(group, draftGenerations)`. Every command is persisted before submission. A partition-local monotonic sequence is assigned atomically on first insertion, so recovery preserves enqueue order even when timestamps match; retries keep the original sequence. An ambiguous response blocks replay until explicit `retry()`, preserving every command ID and the exact payload. Changed content requires new IDs. Server receipt validation checks the submitted group, actor, affected IDs and new revisions before acknowledging it. Cleanup cannot erase a newer generation.
8. Update the engine's authoritative base from `onConfirmed`. An edit created while a prior save is pending must be rebuilt against the acknowledged base by the engine adapter. This package does not invent automatic merging or rewrite an immutable submitted command. Unexpected callback failure blocks further work without replaying the already acknowledged command.
9. `flush()` first ends the grouping window, waits for local writes and the active server submission, and returns true only with no unacknowledged draft/command. Use that boolean before close, selection/navigation or export. It does not silently retry after a network error, conflict or expired session.

## Privacy and recovery

A C4 401 suspends the privacy boundary. `resumeAfterAuthentication()` accepts the same user/workspace and authorization version only; it does not retry. The user must then explicitly resubmit. A changed account/version closes the old controller and requires a fresh authorized snapshot/cache. A role/access denial clears that workspace's private cache. Late response callbacks are ignored after expiry, revoke, signout or disposal.

409 keeps both the local content and safe server conflict references. It blocks generic retry. The remaining conflict feature must read the current authorized snapshot to show the server alternative; hashes and IDs are not content. No force overwrite or automatic merge is implemented here.

For `AccountMenu`, wire an explicit confirmation to `prepareConfirmedSignOut("save" | "discard")` through `beforeSignOut`. Saving must return true before exit proceeds. Only confirmed successful signout calls `confirmedSignedOut()` through `onSignedOut`; it closes the boundary and removes all of that user's workspace caches. A false cleanup result must be disclosed, not described as successful device cleanup. Other users' partitions are untouched. Unmounting should call `dispose()` and close the database connection; this cancels the session lease but does not pretend the server mutation was cancelled or discard persisted work.

The IndexedDB cache is local, unencrypted, account-scoped recovery storage, not an authorization authority or a defense against malicious scripts running in the same origin. The authenticated server always enforces access. Do not store authentication/session secrets here. Reopening a cache requires fresh server authority, including after signout or permission changes.

## Evidence and remaining scope

Focused Node tests use `fake-indexeddb`'s actual IndexedDB API implementation with isolated factories. They cover transaction completion, connection reopen, auth/account/workspace/artifact isolation, revocation across connections, abort races, generation ordering, quota errors, stable replay, same-user reauthentication, 409 preservation, receipt mismatch, signout cleanup and grouping/flush. They do not prove disk durability, private mode, browser lifecycle/eviction or cross-browser behavior.

Remaining 03.1 work: real HTTP transport and DB-backed acceptance; last-100 confirmed history persistence/undo/redo; version restore/branch and lifecycle adapters; authorized server alternatives and conflict resolution; localized header/dialogs and mounted user paths. No browser navigation, screenshot, renderer, CUA or browser automation has been used. Visual, keyboard, mobile and engine interaction remain user-owned checks.
